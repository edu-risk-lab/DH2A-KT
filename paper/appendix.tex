\section{Path-derived hyperedges and the leakage taxonomy}
\label{app:hyperedge-construction}
\label{sec:tier1-graph}
Path-derived concept-group hyperedges are bounded-length simple directed
paths on audited, acyclic $E_{\mathrm{pre}}^f$
(Algorithm~\ref{alg:concept-hyperedge}). Each hyperedge collects the
concepts visited along a path as an unordered member set, so path
direction is not retained. These groups are used for the audit and for
optional hypergraph-convolution diagnostic arms
\cite{bai2021hypergraphconv}; they are not inputs of the credited arms.
Chain length bounds $[3,8]$ match \texttt{configs/xes3g5m.yaml}.

\begin{algorithm}[H]
\caption{Path-derived concept-group hyperedges from audited
$E_{\mathrm{pre}}^f$.}
\label{alg:concept-hyperedge}
\begin{algorithmic}[1]
\STATE \textbf{Input:} $E_{\mathrm{pre}}^f$; bounds $[\ell_{\min},\ell_{\max}]=[3,8]$
\STATE \textbf{Output:} path-derived concept-group set $\mathcal{E}^{\mathrm{path}}_f$
\STATE Build directed graph $G$ from $E_{\mathrm{pre}}^f$
\FOR{each root $r$ with in-degree 0 in $G$}
  \FOR{each simple path $p$ from $r$ with $\ell_{\min}\le |p|\le\ell_{\max}$}
    \STATE emit unordered members $\{(\text{concept},c):c\in p\}$
  \ENDFOR
\ENDFOR
\end{algorithmic}
\end{algorithm}

Table~\ref{tab:leakage-taxonomy} lists the three hyperedge-level
leakage classes that a pairwise projection does not express.
Discussion-thread and teacher-intervention hyperedges are data-blocked
on the public corpora; session and hint hyperedges are built on
FoundationalASSIST only (\ref{app:foundational-assist}).

\section{Evaluation protocol details}
\label{app:protocol-detail}
Because the logits at position $t$ predict row $t{+}1$, local index $0$
of a window is never a scored target, and the repeat flag is sliced
from the full-log array rather than recomputed inside the window. A
fold-0 census finds $208$ windows of length $400$ that start on a
globally repeated KC-row; all $208$ also split an attempt across the
boundary, and all are classified as safe because the first row is not a
target. Later KCs of the same attempt remain masked, not pooled.

Tracer arms are scored on $n{=}1{,}093{,}755$ native positions and pyKT
baselines on the library intersection $n{=}1{,}093{,}720$. An occurrence
join on (learner, dense KC, occurrence index) matches $1{,}093{,}718$
rows but is not a stable event identifier: eight joined keys disagree on
the label. The pre-chunk key (learner, timestamp, item, KC) matches the
same $n$ with no label disagreement. Rebasing every arm onto that key
needs stored per-row scores, which are not in the public snapshot, so
baseline gaps remain contextual locations rather than event-paired
differences.

state. The $6{,}413{,}353$ KC-expanded rows versus $5{,}549{,}635$
recorded attempts in \cite{liu2023xes3g5m} is the expansion pyKT warns
about.

\section{Graph-only encoder as a forced-reliance diagnostic}
\label{app:graph-only}
\label{sec:manipulation-result}
A graph-only diagnostic encoder (chain hyperedges, no question LSTM
path; Table~\ref{tab:aliases}) exists so that a destruction check is
interpretable: mean test AUC $0.7516{\pm}0.0015$ against reused GKT
$0.8336{\pm}0.0010$ under the pairwise audit's GKT budget ($L{=}200$;
Table~\ref{tab:auc-xes3g5m-v2}). That gap mixes encoder, budget, and
protocol and is not an isolated architecture cost.

\input{tables/table_auc_xes3g5m_v2}

Frozen-weight node-drop $p{=}0.9$ passes on all three folds
($\Delta$AUC $0.0323$, $0.0606$, and $0.0574$ on a shared clean AUC
per fold). GKT also drops after retraining on a destroyed pairwise graph
($0.0877{\pm}0.0009$); the protocol differs (freeze versus retrain).
Node-drop confirms dependence on some graph input. Degree-preserving
rewiring passes on folds~0--2 ($\Delta$AUC $0.0318$, $0.0341$, $0.0351$;
shared clean $0.7485$/$0.7511$/$0.7521$), so this encoder is sensitive
to co-occurrence structure. Relation-label permutation is near-null on
every fold (Table~\ref{tab:manipulation}). Dropping the auxiliary
graph-sensitivity loss on the fold~0 track still yields clean AUC
$0.754$ and $\Delta$AUC $0.039$. The credited arms do not take this
check: concept-level convolution is off there, and question--KC
incidence is a bipartite membership matrix rather than a multi-way
graph. We do not deploy this encoder.

\subsection{Descriptive structural overlap on Junyi}
\label{app:junyi-gt}
\label{sec:junyi-gt}
Table~\ref{tab:junyi-gt} compares hyperedge-chain overlap and the
pairwise $E_{\mathrm{pre}}$ against the Junyi expert DAG at
$K{=}|$expert$|$. Edge F1 is $0.165$ (hyperedge chain) against $0.183$
($E_{\mathrm{pre}}$) on fold~0; folds~1--2 are analogous. Collapsing
directed paths into multi-node hyperedges and projecting back to pairs
can dilute expert-edge recall. This is a descriptive overlap measure,
not validation of construction fidelity and not evidence that chain
hyperedges improve prediction. A degree-preserving random-graph null is
future work.

\subsection{FoundationalASSIST}
\label{app:foundational-assist}
\label{sec:foundational-assist}
FoundationalASSIST \cite{foundationalassist2026} provides about
1.74~million skill-linked interactions with synchronised hint counts
(hint-use rate $5.2\%$). Under the same learner split (fold~0) we infer
train-only $E_{\mathrm{pre}}$ (280 edges after cycle pruning), build
5{,}840 path-derived concept groups, and construct 308{,}670 session
hyperedges on training learners ($11.6\%$ with a hint member;
$\mathrm{ECR}^{\mathrm{flag}}{=}0$, group-membership leak $0$). The
tracer reaches fold~0 AUC $0.720$ with concept groups alone
($n{=}298{,}500$ predictions); adding up to 20{,}000 multi-concept
session hyperedges raises it to $0.722$. That shift is not a
hypergraph-AUC claim: the isolated hint-item hyperedge arm stays below
the rule (Table~\ref{tab:negative-knowledge}). On this corpus query-only
$\Delta t$ keeps most of the gain of the package ($+0.01471$ against no
time), LSTM-only gives $+0.00280$, and adding the previous step's
answer-viewing flag to the package adds a further $+0.00297$. These are
single-seed diagnostics.
